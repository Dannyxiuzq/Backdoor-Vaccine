## 0. 摘要

本工作在 Backdoor-Vaccine 仓库中**新增了一条训练期后门免疫防御 SAART-P1（Self-Adversarial Consistency Immunization，自对抗一致性免疫）**，与原方法 BD-VAX（后处理 / 权重差分净化）并行共存。SAART-P1 的威胁模型是：给定一个疑似带后门的 LoRA adapter（θ_sus）+ 一批 clean 数据，**没有干净 reference model、也没有真实 trigger**，直接在 θ_sus 上续训消解后门。其训练目标为 `total = L_clean + λ1·L_adv-correct + λ2·L_output-cons`：用一个内层 soft-trigger 自对抗者在 response 区做 FGSM-sign 梯度上升、最大化"行为无关的输出偏移代理 KL"，外层则同时最小化干净 CE、对抗样本上的纠正 CE、以及触发/无触发输出一致性。

围绕"方法是否合理"，我们设计并跑完了 **4 波后台编排、共 21 个新对比条件**，连同仓库已有的 7 个 BD-VAX baseline 行，构成 **28 条件**的完整对比矩阵（全部跑在空闲的 GPU 8/9 上，未触碰其他用户在 0–7 上的任务）。核心结论（合理性"4+1 支柱"）：

1. **有效**：最佳 SAART = `after_bos + λ2=0.5 + pool`，**Trigger ASR = 9.0%（−36.5pp，Clean FP = 0）**，胜过所有 finetune / 剪枝 baseline，仅次于 BD-VAX 的 suppress+FT（3.0%，后处理 + 权重 signature 更强）。
2. **不是"算力堆出来的"**：compute-matched 纯 finetune（5/24/48 epoch → 20.5 / 41.0 / 47.5%）随训练量**单调更差**，SAART 领先 +20 ~ +26.5pp——这是排除"只是 finetune 更久"质疑的最强证据。
3. **机制可解释**：`adv-correct` 的 CE 是主力（去掉后退化到 35%）；对抗搜索比随机触发对照仅 +2.5pp（真实但温和，inner=3 后饱和）；null-ref 贡献约 +4pp；pool 近似中性。并发现一个**非平凡的"位置 × KL 交互"**。
4. **稳定**：3 seed → 21.0 / 19.0 / 24.5%，均值 21.5% ± 2.27pp。
5. **vs consistency-only（CROW 式，16.0%）**：主 config（prompt_end，21%）反而输 5pp，但最佳 after_bos（9%）胜 7pp——自对抗触发器只有在**正确的插入位置**才优于纯一致性正则。

诚实保留：(a) P2 阶段把默认 `insert_position` 翻成了 `prompt_end`，对本攻击在经验上是错的，应改回 `after_bos`（或按攻击可配）；(b) BD-VAX 后处理（3.0%）依然更强；(c) 仅单攻击 × 单模型，跨攻击 / 跨模型未做（P3 方向）。

## 1. 背景与动机

### 1.1 原方法 BD-VAX 是后处理防御

仓库原方法 BD-VAX（Backdoor Antigen / Vaccine）是一条**后处理、基于权重差分**的后门净化流水线：训练 N 组 variant adapter 对（poisoned / clean）→ 抽取 poisoned−clean 的权重 signature → 把 signature 通道置零 → 做一遍轻量 clean finetune。它在已有 9 模型矩阵上于 8/9 个模型最优，但本质是"先训出 signature 再外科切除"，依赖额外的 N×2 个 variant adapter 与签名抽取阶段。

### 1.2 SAART-P1 是训练期免疫，与 BD-VAX 并行共存

按内部文档《自对抗关联鲁棒训练框架》+ 一轮评审意见，本工作新增了一条**训练期、基于自生成触发器的免疫防御**：不抽签名、不切通道，而是在续训过程中**自己合成对抗触发器并就地免疫**。设计目标是与 BD-VAX 解耦、可独立运行（BD-VAX 仍保留为 baseline）。其威胁模型比 BD-VAX 更"瘦"：只需要 θ_sus + clean 数据，**不需要 variant 对、不需要真实 trigger、不需要 reference model**。

本报告即记录该方法从落地到合理性论证的全过程。文档与评审来源：仓库根目录 `自对抗关联鲁棒训练框架_研究重构建议.md`，以及评审给出的 P0/P1 要点（见 §3.5）。

## 2. 方法（SAART-P1）

### 2.1 每步训练目标

SAART-P1 在每个训练 step 上最小化

```
total = L_clean + λ1 · L_adv-correct + λ2 · L_output-cons
```

- **L_clean**：在干净样本上的标准 SFT 交叉熵（保效用 / 锚住正常行为）。
- **L_adv-correct**：把内层搜出来的 soft trigger 插入输入后，**仍要求模型给出正确（clean）的 response** 的交叉熵——即"即便被触发，也要纠正回正常输出"。这是免疫的核心监督信号。
- **L_output-cons**：触发分支与无触发分支在 response 区上的输出一致性正则（KL）。

默认权重 `λ1 = 1.0`、`λ2 = 0.5`。

### 2.2 内层 soft-trigger 自对抗者

内层是一个**行为无关的输出偏移最大化器**：在连续 embedding 空间放置一个长度 k 的 soft trigger，用 **FGSM-sign 梯度上升**最大化 response 区的

```
KL( p_ref(· | x ⊕ t_null) ‖ p_theta(· | x ⊕ soft) )
```

其中 `t_null` 是等长的中性参考触发器（见 §2.3）。这个代理"行为无关"——它只追求让输出分布**偏移**，不假设后门的具体恶意行为，因此不依赖真实 trigger 的知识。默认 `inner_steps = 3`、`inner_lr = 0.03`、`trigger_len = 5`。

关键工程纪律（见 §3.5 P0）：内层用 `torch.autograd.grad` 求梯度，**绝不调用 `.backward()` / `model.zero_grad()`**，以免污染 LoRA 梯度、破坏梯度累积。

### 2.3 null-trigger 参考分支（消位置偏移）

仅仅"插入一个 trigger"本身就会改变序列长度与位置编码，导致 KL 里混入纯位置偏移伪影。为此引入一个**等长、detached 的中性参考触发器** `t_null`（默认 `mean_embedding`，另有 `zero` / `pad_token` 变体），让参考分支与触发分支在长度 / 位置上对齐，KL 才度量"真正的分布偏移"而非"插入造成的位移"。

### 2.4 插入位置

触发器插入位置可配：`after_bos`（紧跟 BOS）或 `prompt_end`（prompt 末尾）。`_build_triggered_inputs` 在 per-example 位置把 `[B,k,d]` 的 trigger embed 拼进 `[B,S,d]`，trigger 段 attention=1、label=IGNORE_INDEX，输出 S+k 长度的 `(embeds*, attn*, labels*)`。**本报告的核心发现之一是该位置选择与 KL 权重存在强交互**（见 §7.3）。

### 2.5 离散 HotFlip-lite 投影 + EMA top-k trigger pool

为让"自对抗触发器"真正可解释、并跨 step 复用：

- **投影**：`_project_tokens` 用归一化余弦把 soft trigger 投到最近的离散 token id（HotFlip-lite），排除特殊 token（`_bad_token_ids`）。默认 `proj_every=20`、`proj_keep_frac=0.8`。
- **离散 trigger pool（方案 A，真正参与训练）**：`_add_to_pool` / `_evict_pool` 维护一个按 token 序列去重的池，每个条目带一条 **EMA** 运行代理值（`pool_ema_beta=0.9`）；eviction 策略 `topk_ema`（保留高 EMA，P2 默认）或 `fifo`。训练时以 `pool_sample_prob=0.3` 概率从池里抽离散 trigger 复用，使池中触发器**真正进入训练图**而非仅作日志。

### 2.6 其它设计要点

- soft trigger 在 batch 内共享 + 全局 seed（`use_global_soft_seed=True`）+ 对称破缺初始化（否则 KL 在 init 处梯度为 0）。
- eval 阶段退回普通 SFT loss（不触发自对抗免疫）。
- KL 支持 forward / reverse / symmetric / js（默认 forward）。
- compute_loss 只返回 **clean** 分支的 outputs，使触发 / 内层图不会泄漏到外部。

`saart_trainer.py` 关键方法：

- **`compute_loss(model, inputs, return_outputs, num_items_in_batch)`** — 组装 `total = L_clean + λ1·L_adv_correct + λ2·L_output_cons`；eval 模式退回普通 SFT；守卫 `S+k > max_position_embeddings`；只返回 clean outputs；自增 `_step_counter`。
- **`_inner_search(...)`** — 内层 soft-trigger 对抗者，对 `KL(p_ref ‖ p_soft)` 做 FGSM sign-ascent；用 `torch.autograd.grad`（绝不 `.backward()` / `model.zero_grad()`），不污染 LoRA 梯度、保护累积；可选 `model.eval()` 内层循环；持久化 `_global_soft_seed`。
- **`_select_response_logits(logits, labels)`** — causal shift：`shift_logits = logits[:, :-1]`，`shift_labels = labels[:, 1:]`，mask 掉 `IGNORE_INDEX`，返回 `[num_resp_tokens, V]`，保证 k-shift 后 adv / ref token 数对齐。
- **`_build_triggered_inputs(...)`** — per-example 位置拼接 trigger embed；trigger attention=1、label=IGNORE_INDEX；输出 S+k。
- **`_null_trigger_embeds(...)`** — detached 中性等长参考触发器，消位置偏移。
- **`_project_tokens(...)`** — HotFlip-lite 最近邻投影，排除特殊 token。
- **`_add_to_pool` / `_evict_pool`** — 离散 trigger 池，按 token 序列去重 + 每条目 EMA 更新；`topk_ema` / `fifo` eviction。
- 支撑：`_kl`、`_insertion_positions`、`_init_soft_trigger`（对称破缺）、`_maybe_clip_soft`、`_project_and_update_pool`、`_use_pool_trigger`、`_discrete_trigger_inputs`、`_sanity_check`、`_maybe_log`。

`SAARTArguments` 主要默认值：`saart_insert_position = prompt_end`（dataclass 默认；experiment.yaml 亦设 `prompt_end`）、`saart_pool_policy = fifo`（dataclass 默认；experiment.yaml 在 P2 覆盖为 `topk_ema`）、`saart_trigger_len=5`、`inner_steps=3`、`inner_lr=0.03`、`lambda1=1.0`、`lambda2=0.5`、`pool_size=16`、`use_projection=True`、`proj_every=20`、`proj_keep_frac=0.8`、`use_global_soft_seed=True`、`kl_type=forward`、`pool_sample_prob=0.3`、`pool_ema_beta=0.9`。

## 4. 实验设置

### 4.1 模型 / 攻击 / 数据

- **模型**：LLaMA-2-7B-Chat（`/mnt/data/model/Llama-2-7b-chat-hf`，bf16，LoRA / adapter-only）。
- **攻击**：BadNets × Sentiment Steering（负向情感操纵），与仓库主实验完全一致。
- **威胁模型**：给定 θ_sus（疑似带后门 LoRA）+ clean 数据，无 reference、无真实 trigger，在 θ_sus 上续训消解。SAART 免疫从 θ_sus 续训、在 `finetune_clean` 上做。

### 4.2 评测协议

- 200 trigger + 200 clean 测试样本；仓库关键词式 ASR judge（与 CROW 协议一致，不改判定逻辑）。
- **Trigger ASR 越低越好**；**Clean FP 应保持低位**（误报）。
- `results.jsonl` 只追加，按 timestamp 取每 tag 最新一条。

### 4.3 GPU 编排

4 波后台编排，**仅使用空闲的 GPU 8/9**（未触碰其他用户在 0–7 上的任务），每卡并行 3 个 SAART adapter。各波之间显式 wait（wave2 等 wave1、wave3 等 wave2、wave4 等 wave3 + 等卡空闲）。

### 4.4 compute-match 方法（关键）

为排除"SAART 只是 finetune 更久"的质疑，按 **train_runtime 对齐算力**：SAART immunize 实测 **830.45s（5 epoch）**，纯 FT B2 实测 **171.68s（5 epoch）**。

- 1×（≈ SAART 算力）→ 24 epoch（实测 918.03s）
- 2×（≈ SAART 算力 ×2）→ 48 epoch（实测 1780.19s）

各 run 的 `all_results.json` 实测训练时长：

| run | train_runtime (s) | epoch |
|---|---:|---:|
| `saart_p1/immunized` | 830.45 | 5.0 |
| `pure_finetuned`（B2）| 171.68 | 5.0 |
| `pure_finetuned_long`（1×）| 918.03 | 24.0 |
| `pure_finetuned_long2`（2×）| 1780.19 | 48.0 |
| `consistency` | 523.12 | 5.0 |

## 6. 合理性分析（4+1 支柱）

### 6.1 支柱①：有效

最佳 SAART（after_bos + λ2=0.5 + pool）**Trigger ASR = 9.0%，Clean FP = 0**，相对无防御 −36.5pp，胜过所有 finetune / 剪枝基线，**仅次于** BD-VAX 后处理（3.0%）。后处理凭借显式权重 signature 外科切除天然更强，这一差距在预期之内、且是诚实记录（见 §7）。

### 6.2 支柱②：不是算力堆出来的（最强证据）

compute-matched 纯 FT 在等算力 / 双倍算力下分别只到 41.0% / 47.5%，**随训练量单调恶化**且 2× 甚至劣于无防御（200 条 clean 上过训漂回后门）。SAART 主 config 领先 1×/2× 各 +20.0 / +26.5pp，最佳更领先 +32.0 / +38.5pp。"更久 finetune"不仅不能复现 SAART 的效果，反而有害——SAART 的增益来自机制而非算力。

### 6.3 支柱③：机制可解释

- **adv-correct CE 是主力**：去掉它（`kl_only`）退化到 35.0%（+14pp），是最严重的单组件退化。
- **对抗搜索真实但温和**：inner0（随机触发，23.5%）vs 主 config（inner=3，21.0%）仅 +2.5pp，inner=5 饱和——自对抗带来真实增益但非主导，搜索 3 步已够。
- **null-ref 贡献 +4pp**：`no_null`（25.0%）vs 主 config（21.0%），消位置偏移确实帮助 KL 度量真实分布偏移。
- **pool 近似中性**：`soft_only`（−pool，20.5%）vs 主 config（21.0%）几乎无差——pool 在此设定主要价值是可解释性 / 复用，而非直接降 ASR。

### 6.4 支柱④（非平凡发现）：位置 × KL 交互

这是本批实验最有价值的结构性发现：**插入位置与 KL 权重强交互，二者不可独立调。**

- 在 **prompt_end** 下，KL 是**负作用**：λ2 越大越差（0.25→0.5→1.0→2.0 ⇒ 19.5→21.0→30.5→28.5%），且 `adv_only`（−KL，16.0%）优于带 KL 的主 config（21.0%）。
- 在 **after_bos** 下，KL 是**正作用**：保留 λ2=0.5（9.0%）优于把 KL 关掉的 `bos_best`（λ2=0，12.5%）。

因此 wave-3 的直觉假设"把两个看似获胜的轴（after_bos + 关 KL）叠加 = 最佳"被证伪——叠加反而变差（12.5%）。最佳配置是 **after_bos + λ2=0.5（9.0%）**。这说明 KL 一致性正则的有效性依赖触发器插入在何处使分布偏移"可被纠正"，是一个需要联合调参的非平凡耦合。

### 6.5 支柱⑤：稳定 + vs consistency-only

- **稳定**：3 seed 均值 21.5% ± 2.27pp。
- **vs consistency-only（CROW 式，16.0%）**：主 config（prompt_end，21.0%）**反输 5pp**，但最佳 after_bos（9.0%）**胜 7pp**。结论需诚实分两面陈述——**自对抗触发器只有在正确插入位置（after_bos）时才优于纯一致性正则**；在错误位置（prompt_end）反而不如纯一致性。这进一步印证 §6.4 的位置耦合。

---

## 7. 诚实局限与建议

1. **默认插入位置应改回 after_bos。** P2 阶段把 dataclass / experiment.yaml 的默认 `insert_position` 翻成 `prompt_end`，经验上对本攻击是**错的**（21.0% vs after_bos 的 9.0%）。建议把默认改回 `after_bos`，或将其设为按攻击 / 模型可配并文档化这一耦合（§6.4）。当前主 config 报出的 21.0% 因此**低估**了方法的真实能力。
2. **BD-VAX 后处理仍更强（3.0% vs 9.0%）。** SAART 是更"瘦"威胁模型下（无 variant 对、无 signature 抽取）的训练期方案，定位互补而非取代；不应声称 SAART 超过 BD-VAX。
3. **仅单攻击 × 单模型。** 全部结论基于 LLaMA-2-7B-Chat × BadNets × negsentiment。跨攻击（VPI / Sleeper / jailbreak）、跨模型（RQ5/RQ6）尚未验证，是 P3 方向。
4. **consistency-only 在错误位置下更优。** 在采纳 SAART 主 config 之前必须先修默认位置，否则与最简单的一致性正则相比并无优势。
5. **评测仍是关键词 judge。** 与仓库一致；clean-FP 关键词指标对语义退化盲视（仓库 Llama-3.1 教训），不过本批 SAART 的 clean-FP 均为 0–0.5%，无明显退化迹象。

## 8. 结论与后续工作

### 8.1 结论

SAART-P1 作为一条**训练期、自对抗、免疫式**后门防御已落地并跑通完整合理性 battery：最佳配置在 LLaMA-2-7B-Chat × BadNets 上把 Trigger ASR 从 45.5% 降到 **9.0%（−36.5pp，Clean FP 0）**，胜过所有 finetune / 剪枝 / 一致性基线，且经 compute-match 严格排除"算力效应"、经 ablation 归因到 adv-correct 主力 + null-ref + 温和对抗搜索、经 3 seed 验证稳定。最有价值的科学发现是**位置 × KL 交互**——一致性正则的有效性依赖触发器插入位置，二者必须联合调。诚实地说，BD-VAX 后处理（3.0%）仍更强，SAART 定位为更瘦威胁模型下的互补训练期方案。

### 8.2 后续工作（P3）

1. 把默认 `insert_position` 改回 `after_bos`（或可配 + 文档化耦合），并把"位置 × KL"做成正式的二维 sweep。
2. 跨攻击（VPI / Sleeper / jailbreak）× 跨模型矩阵（RQ5/RQ6），复用仓库多后端流水线，验证"after_bos 优势 / 位置耦合"是否普适。
3. 推进框架文档的 P3：**在线 MLP 关联签名 + L_assoc-reg**（关联鲁棒正则），把 SAART 与 BD-VAX 的"签名"思想在训练期统一。
4. 在 Step 5 增加语义级输出质量指标（乱码率 / 困惑度 / LLM judge），避免关键词指标对退化盲视。

# 补充：Phase-2（Module 2）—— 在线 MLP 关联签名 + L_assoc-reg 结果（2026-06-08）

## P2.1 方法补充
在最佳 P1 设定（after_bos + λ2=0.5 + pool）之上接入文档 **Module 2**：训练中用 forward hook 采 clean / triggered 两遍的 MLP 通道激活，
算 response 区激活差 Δh，在线 EMA 统计每通道风险，每 module 取 top-τ% 高风险通道集 S，对 S 上的 Δh 施加第 4 项损失
`L_assoc-reg = mean_{j∈S}(Δh_j)²`（迫使触发前后高风险通道激活一致，从内部切断 trigger→behavior 关联）。
开启 `use_assoc_reg` 时自动关 gradient checkpointing（保证 adv 激活带梯度），用 batch=1 控显存。
> 实现注记：`L_assoc-reg` 对 S 取**均值**而非文档写的求和——求和会因 |S|≈3852/模块把损失放大到上千、压垮训练发散；均值归一到 O(1)。

## P2.2 主结果：Module 2 进一步降 ASR
| 条件 | Trigger ASR | Clean FP | 说明 |
|---|---:|---:|---|
| no_defense (θ_sus) | 45.5% | 0.5% | 无防御上界 |
| P1 best (after_bos, λ2=0.5) | 9.0% | 0.0% | 仅输出层面损失 |
| **P2 (+ L_assoc-reg)** | **5.0%** | 0.0% | 叠加内部关联正则化 |
| **P2 best (λ3=3.0)** | **4.5%** | 0.5% | 全场 SAART 最优（−41.0pp） |
| BD-VAX suppress+FT（后处理） | 3.0% | 0.0% | 仍最强（用 variant signature） |

**结论**：在线 MLP 关联签名 + L_assoc-reg 把 ASR 从 9.0%→5.0%（−4.0pp），即 **45.5%→5.0%（−40.5pp）, clean_fp 0**；
训练期 SAART 已**逼近后处理 BD-VAX(3.0%)**，且无需训练 variant adapter / 抽权重 signature。

## R6.2 关键结论

1. **泛化性成立：SAART 在全部 12 个模型上都降 ASR**（P2 相对 no_def −6.5pp ~ −69.5pp），且多数 `clean_fp=0`。训练期自对抗免疫不依赖特定基座。
2. **SAART 在"后处理 BD-VAX 失灵"的模型上反超**（这是训练期防御的独特价值）：
   - `llama3_1_8b_instruct`：BD-VAX 几乎无效(72.5→69.5)，SAART-P2 降到 32.5；
   - `meta_llama_3_8b_instruct`：BD-VAX 15.0 vs SAART-P2 **3.0**；
   - `llama3_chinese_8b`：BD-VAX 8.0 vs SAART-P2 **0.5**。
   说明当 variant-signature 难以定位通道时，自对抗"遗忘 trigger→behavior 关联"仍奏效，两法**互补**。
3. **BD-VAX 仍在另一批模型上更强**（gemma 1.5、llama2 3.0、qwen2/qwen2.5/qwen3 家族），即后处理通道净化对这些模型的后门更"对症"。**没有单一赢家**——最佳实践是二者并用、取 min。
4. **Module 2(assoc-reg) 不是普遍增益（重要负面发现）**：P2 在 8/12 模型上 ≤ P1（降得更多或持平），但在 **qwen2.5-7B(+11pp)、qwen2-7B(+10.5pp)** 上明显**变差**，qwen3-1.7B 持平。即在线 MLP 关联签名对 qwen2 家族选出的高风险通道，与输出层免疫产生了**负向权衡**（训练本身健康：loss_assoc≈0.1–5、|S|≈12万通道、梯度正常）。**结论：assoc-reg 应作为可调开关而非默认**，对 qwen2 家族建议关闭(退回 P1)。
5. **最难的两个模型**：vicuna(97.5→81)、mistral(97.5→68.5)——超高基线 ASR，SAART 与 BD-VAX 都只能部分压制；vicuna 还伴随 clean_fp 14.5%（该基座 clean 行为脆弱）。是后续(更强内层搜索 / 更高 λ)的开放挑战。

## R6.3 工程：让 24 cell 真能在共享 10 卡上跑完（本轮踩坑与修复）

- **P2 关 GC → 改非重入 GC**：原实现开 assoc 时直接关梯度检查点(保证 adv 激活带梯度)，导致两类失败：
  ① gemma-9B P2 关 GC 峰值~42GB 超 40GB 卡；② **qwen2/qwen2.5-7B P2 关 GC 时 bf16 数值不稳→首个优化步梯度范数=0/NaN，触发 DeepSpeed `assert all_groups_norm > 0`**。
  修复：保持 GC 开启但切 **`use_reentrant=False`**（非重入：初始前向正常建图、仅丢中间张量待反向重算→hook 抓的激活仍带梯度，同时省显存）。
  落地 `checkpointing.py`(读 `model_args.saart_nonreentrant_gc`)+`saart_workflow.py`。修复后 qwen2/qwen2.5/qwen2_7b/gemma-9B 的 P2 全部跑通，14 单测仍全过。
- **P1 显存峰值被低估**：`saart_p1` 默认 `batch=8`（填卡策略），但 8B 的内层对抗搜索(3 步)+null/triggered 多次前向使峰值逼近 40GB。
  qwen3-8B P1 改 `batch=2/accum=4`（有效批量不变）后稳定在 24.8GB。
- **大模型只用整卡 + `expandable_segments:True`**：9B/8B 这类峰值~40GB 的 cell 只派到全空卡，并开 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 回收碎片（曾仅差 66MiB OOM）。
- **评测 fp32 不能 CPU-offload**：`step5_evaluate.py` 用 `torch_dtype=float32`(7B≈30GB)，在 co-located 卡(可用~27GB)上 `device_map=auto` 会把 embed 卸到 CPU→前向 `cpu vs cuda` 设备不匹配崩。修复：qwen2/qwen2.5 的 P2 评测改派到 free≥32GB 的卡。
